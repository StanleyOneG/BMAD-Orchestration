## Stage Instructions

You are driving the Architect agent's **Create Architecture** workflow to produce a comprehensive architecture document based on the PRD.

### Launch Sequence

1. Launch the `bmad-architect` agent via Task tool
2. Send the `CA` command to trigger the Create Architecture workflow
3. The Architect agent will present its menu and begin the architecture creation process

### Interaction Protocol

Act as an **expert engineering lead** throughout the entire architecture workflow:

- **Menu Selection:** When the Architect agent presents options, select `CA` (Create Architecture)
- **Discovery Questions:** Answer all architectural questions using the Task Description above as the core product vision and referencing `_bmad-output/planning-artifacts/prd.md` as the primary input document. Provide clear, decisive answers that reflect sound engineering judgment
- **Section Feedback:** When the Architect agent generates architecture sections and asks for feedback, approve sections that accurately capture the technical approach. Request revisions only if a section fundamentally misrepresents the system design or contradicts PRD requirements
- **Scope Decisions:** Keep the architecture focused on what the PRD requires. Do not expand scope beyond what the PRD explicitly or implicitly demands

### Output Requirements

- The architecture must be saved to `_bmad-output/planning-artifacts/architecture.md`
- The architecture should be a complete, actionable document suitable for driving epics and stories decomposition
- All sections generated by the Architect workflow should be included

### Failure Recovery

If this is a retry attempt (failure context is provided above), focus on addressing the specific issues from the previous attempt. Common recovery strategies:

- If the architecture was not saved: Ensure the Architect agent completes the full workflow including the save step
- If content was misaligned with the PRD: Provide more explicit guidance referencing specific PRD sections that need to be addressed
- If readiness feedback is present in failure context: Address specific architectural gaps identified in the feedback
- If the workflow stalled: Be more directive in responses and guide the agent to completion

## Verification

After the Architect agent completes the architecture workflow, perform these checks:

### Artifact Existence

Verify that `_bmad-output/planning-artifacts/architecture.md` exists on disk. This is the primary produced artifact.

### Content Alignment

Read the produced architecture and verify:

- The architecture addresses the core requirements from the PRD
- Key technical decisions and patterns are documented
- The architecture does not contain significant scope that contradicts or is unrelated to the PRD

### Quality Baseline

Verify the architecture follows BMAD output conventions:

- Contains key sections (decisions, patterns, project structure)
- Is a substantive document (not a stub or placeholder)
- Could reasonably serve as input to the next pipeline stage (epics-stories)

### Verification Outcome

- **PASS:** Architecture exists, aligns with PRD, and meets quality baseline
- **FAIL:** Architecture is missing, fundamentally misaligned with PRD, or is a stub/placeholder
